# AGENTS.md (for Codex and other coding agents)

Read `SYSTEM.md` first. It defines the mission, the 13 sections, the honesty rules and the quality gates.

## Your role here: QA reviewer
- Follow `Agent/qa.md` exactly.
- You **report**, you do not fix. Do not edit anything except `workspace/04-qa-report.md`.
- Claude Code applies fixes, so the two tools never edit the same files.

## Hard rules
- Never invent clients, testimonials, metrics or credentials, and never suggest adding them. Gaps stay as `[REPLACE: …]`.
- Never read, print or request secrets (`.env*`, Supabase keys). Use `app/.env.example` only.
- Do not deploy, push, open PRs or change git history.
- Do not skip, disable or weaken a test to make it pass.

## Project map
| Path | What |
|---|---|
| `SYSTEM.md` | Rules and quality gates |
| `Agent/` | Agent definitions (research, consolidate, copy, build, QA) |
| `workspace/` | Stage outputs. QA writes `04-qa-report.md` |
| `app/content/copy.json` | Single source of page copy |
| `app/components/sections/` | The 13 sections |
| `app/app/api/lead/route.ts` | Lead endpoint |
| `app/tests/` | Playwright end-to-end tests |

## Commands (run from `app/`)
- `npm install`
- `npm run lint`
- `ALLOW_PLACEHOLDERS=1 npm run build`
- `npm run test:e2e` (starts its own dev server on port 3200)

`app/AGENTS.md` (generated by Next.js) also applies to files under `app/`: this Next.js version has breaking changes, so read `app/node_modules/next/dist/docs/` before judging framework usage.
